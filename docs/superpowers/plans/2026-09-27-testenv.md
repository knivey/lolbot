# Test Environment System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up dev bots from a fresh DB/config against our real networks via committed per-network profiles, plus a terminal driver client to interact with the bot under test.

**Architecture:** A `library/testenv/` core (profile loading with gitignored secrets overlay, fresh-sqlite lifecycle with migrations + seeding) driven by a plain-argv `testenv.php` tool that generates the bot config and execs `lolbot.php` with a config-path env override; a slim Amp-based driver REPL reusing `library/Irc` message parsing. Committed profiles: `ownnet` (default, no-services), `gamesurge`, `libera`, `all`.

**Tech Stack:** PHP 8.1, Doctrine ORM/migrations (sqlite scratch DBs), Symfony YAML, Amp v3 (sockets + STDIN), `library/Irc\Message` parsing.

**Spec:** `docs/superpowers/specs/2026-09-27-testenv-design.md` — the plan argues from the spec; executors read both.

## Global Constraints

- PHP 8.1 floor; no syntax above 8.1.
- **Never read or write the prod `config.yaml` database or the dev sqlite** — the tool touches only `testenv/run/` artifacts; enforce the `testenv/run/` path prefix in code. (Exception: Task 6 READS config.yaml once to copy the ownnet server address into the committed profile — read-only, and never copies secrets into committed files.)
- Secrets (SASL passwords) never in committed files — only `testenv/secrets.yaml` (gitignored) with a committed `testenv/secrets.example.yaml`.
- Test channels only; dev nicks distinct from prod bots (per-profile values).
- Existing comments preserved verbatim everywhere (AGENTS.md); never `git add -f` (add the .gitignore entries so plain `git add` works).
- Commits: `git -c user.name="knivey" -c user.email="knivey@botops.net" commit -m "..."` — only the task's files, no push.
- Verification per task: `vendor/bin/phpunit` full suite green; `php -d memory_limit=1G vendor/bin/phpstan analyse <touched paths> --no-progress` zero NEW; TDD red before green where a unit surface exists; scratch files under `/tmp/opencode`.
- Composer PSR-4 `library\` → `library/` already exists — new code goes in `library/testenv/` (namespace `library\testenv`) and autoloads with no composer changes.

## Review Focus

The five failure modes the spec implies but happy-path tests miss. Each pinned in its owning task:

1. **Profile with a missing/typo'd required key must fail with a clear error naming the key** — not a silent default, not a Doctrine crash three layers later. Pinned in Task 2 (`ProfileTest`: missing `networks`, missing server `address`, missing bot `name`, bad YAML type).
2. **Migrations must run BEFORE seeding on the fresh DB** — seeding into an unmigrated DB is a raw SQL error. Pinned in Task 3 (`SeederTest` asserts doctrine_migration_versions contains the latest version AND seed rows are queryable post-seed).
3. **Path isolation: the run DB must live under `testenv/run/` no matter what a profile says** — a malicious/mistyped `db` path must be refused. Pinned in Task 3 (`SeederTest` refuses `../evil.sqlite` and an absolute path).
4. **The generated config must actually boot the bot's bootstrap** — a syntactically valid YAML that Doctrine rejects is a broken `up`. Pinned in Task 4 (subprocess: `LOLBOT_CONFIG=<generated> php -r 'require "bootstrap.php";'` exits 0 and the EM connects to the run DB).
5. **Driver client output must not be corrupted by control chars/CTCP in traffic** — raw `\x01ACTION...\x01` or color codes in a printed line garble terminals. Pinned in Task 5 (`formatLine()` tests: CTCP collapsed, `\x03` color codes stripped, newlines in payloads neutralized).

<?php
// tests/TestEnv/RealProfilesTest.php
use library\testenv\Profile;
use PHPUnit\Framework\TestCase;

class RealProfilesTest extends TestCase
{
    /** @dataProvider profileProvider */
    public function test_real_profile_loads_and_pins_engines(string $name, string $net, array $expectEngines): void
    {
        $p = Profile::load($name);
        $nets = array_column($p->networks(), null, 'name');
        $this->assertArrayHasKey($net, $nets, "profile {$name} lacks network {$net}");
        $this->assertSame($expectEngines, $nets[$net]['auth_engines']);
        foreach ($nets as $n) {
            $this->assertNotEmpty($n['servers']);
            $this->assertNotEmpty($n['bots']);
            foreach ($n['bots'] as $b) {
                $this->assertNotSame('', $b['name']);
            }
        }
    }

    public static function profileProvider(): array
    {
        return [
            ['ownnet', '<OWNNET_NAME>', ['hostmask', 'manual']],
            ['gamesurge', 'gamesurge', ['vhost', 'whox', 'hostmask', 'manual']],
            ['libera', 'libera', ['account-tag', 'hostmask', 'manual']],
        ];
    }

    public function test_all_profile_contains_all_three(): void
    {
        $p = Profile::load('all');
        $this->assertCount(3, $p->networks());
    }
}
